# Установка Graph агентом на компьютере владельца

## Задача

Установить Graph Studio v0.3.0 на Windows x64 вместе с Herdr, подготовить библиотеку и ярлык рабочего стола. Не переносить настройки, токены или личные материалы автора. Не запускать платные модельные задачи без поручения владельца.

## Последовательность

1. Уточни постоянную папку установки и реальный проект владельца. Распакуй официальный ZIP либо клонируй https://github.com/nikolaikrasilnikov/Graph. При наличии SHA256SUMS.txt сравни Get-FileHash архива с опубликованным значением.
2. Прочитай README.md и scripts/dependencies.lock.json. Запусти Setup.cmd. Для воспроизводимой установки всех закреплённых инструментов: powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -UseBundledTools. Настройка не требует npm install, не делает модельных вызовов и не публикует данные.
3. При необходимости передай -LibraryRoot, -DataRoot, -Port и -DesktopDirectory. Путь рабочего стола по умолчанию определяется Windows, в том числе для OneDrive. Не используй личные пути из чужой среды. Существующий config.json сохраняется; для сознательной перенастройки используй -Reconfigure со всеми желаемыми параметрами.
4. Подготовь библиотеку до запуска задачи. Установщик создаёт library из library-template только для отсутствующих файлов. Заполни projects/example/BRIEF.md данными владельца или создай отдельную папку проекта: цель, код, команды проверки, критерии готовности, ограничения. Сохрани неизвестное как вопрос, не выдумывай команды тестов. Не копируй весь репозиторий, секреты или логи в библиотеку.
5. Подключай краткие общие ограничения как общие вложения; большие материалы и skills — планировщику для выбора по этапам. memory пополняй только проверенными выводами. Инструменты/MCP из SKILL.md не появляются автоматически: проверяй фактическую конфигурацию CLI.
6. Владелец самостоятельно завершает Login-Codex.cmd. Не проси передавать токен в чат и не записывай его в библиотеку. Graph использует codex:default, то есть модель из конфигурации CLI. При недоступной модели выбери доступную владельцу и проверь её CLI; имена моделей автора не требуются.
7. Запусти Start-Graph.cmd или ярлык Graph. Проверь http://127.0.0.1:4317/api/health (либо выбранный порт): herdr.ok=true, providers.codex=true, installationRoot указывает на эту установку. Проверь открытие интерфейса и наличие шаблонов в библиотеке. В проекте Graph укажи настоящую рабочую папку исходников, отдельно от библиотеки.
8. Для GitHub владелец запускает Login-GitHub.cmd. Задай owner/repository и проверь готовность в Graph. Только с его разрешения установи githubAgentAuth=true в config.json и перезапусти Graph. Передача авторизации даёт агенту доступ к токену в окружении; gh использует права именно этого аккаунта. Настрой локальные user.name/user.email Git по данным владельца перед первым коммитом.
9. По разрешению владельца проведи небольшой реальный запуск: создать текстовый файл в тестовом проекте, прочитать его следующим этапом и показать итог. Для проверки публикации нужна отдельная явно порученная задача в выбранном репозитории. Не считать наличие gh подтверждением права записи.

## Приёмка

Зафиксируй версии инструментов, проверку хешей, путь локальной установки, наличие ярлыка, успешный health и чтение библиотеки. Отдельно укажи, пройдены ли вход в аккаунт и реальный модельный запуск. Подтверждение локальных тестов не заменяет проверку на новом аккаунте.

При ошибке верни полный полезный текст ошибки без секретов, расположение журнала и следующий шаг. Не сообщай «готово», если сервер, Herdr или авторизация ещё не проверены.

## Обновление и удаление

Перед обновлением останови только процессы этой установки и сохрани config.json, library и .graph-data. Обновляй исходники из релиза, сохраняя эти данные. При изменении набора зависимостей выполни осознанную перенастройку. Не удаляй общий Herdr или чужие процессы. Graph не регистрирует системную службу; удаление его папки и ярлыка не удаляет общую авторизацию CLI, которую владелец управляет отдельно.
