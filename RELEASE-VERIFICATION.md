# Проверка релиза v0.3.0

Проверено на Windows x64, в отдельной копии установки и отдельной сессии Herdr. Это проверка на компьютере разработчика, не на аккаунте получателя.

| Проверка | Результат |
|---|---|
| Автоматические тесты | 61/61: передача зависимостей, продолжение мастера, блокировки, результат неудачной публикации, терминальные события, пути переносимой установки |
| Чистая установка с -UseBundledTools | Все 5 архивов загружены из официальных источников и прошли проверку хешей |
| Node / Herdr / Git / gh / Codex | 24.21.0 / 0.9.1 / 2.55.0.windows.5 / 2.101.0 / 0.155.1 |
| Codex runtime | Есть code-mode-host и необходимые ресурсы; exec --help поддерживает --approve-for-me |
| Запуск Herdr и Graph | herdr.ok=true, providers.codex=true, HTTP 200, правильная installationRoot |
| Настоящий терминал Herdr | Выполнены команды версий Node, Git, gh; их вывод прочитан обратно |
| Ярлык | Создан в тестовой папке рабочего стола; целевой PowerShell, рабочая папка и start.ps1 проверены |
| Повторный Setup | Хеши config.json и изменённого пользователем файла библиотеки не изменились |

В первой попытке обнаружен и исправлен неправильный путь к codex.exe внутри официального архива. Первый запуск Herdr был запрещён песочницей проверяющего агента; при разрешённом локальном запуске отдельная сессия заработала.

Для нового владельца остаются обязательными его вход в Codex, при необходимости GitHub, проверка доступности модели и пробный запуск в его проекте. Открытие health и команды версий не доказывают доступ к модели или право публиковать в чужом репозитории.

Исходники проверяются scripts/check-release.mjs; ZIP создаётся через git archive из очищенного коммита и содержит только отслеживаемые файлы. Скрипт ищет известные виды локальных путей и ключей; он не является универсальной гарантией отсутствия любых секретов. Состав дополнительно просмотрен вручную.
